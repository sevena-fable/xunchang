# 04 · 技术方案与数据语义

## 当前技术栈

| 层级 | 实际使用 |
|------|----------|
| 页面与状态 | React 19、Vite |
| 样式 | Tailwind CSS 4、项目 CSS |
| 动画 | Framer Motion |
| 登录与数据 | Supabase Auth、PostgreSQL、Realtime |
| 照片 | Supabase 私有 Storage |
| 草稿与多窗口保护 | IndexedDB、Web Locks API |
| 音频 | 浏览器 Audio 与 Web Audio API |
| 字体 | Noto Serif SC、霞鹜文楷 |
| 部署 | Vercel |
| 测试 | Node Test Runner、PGlite、Playwright |

## 页面与内容流程

```text
main.jsx → App
            ├── AuthPage：登录、注册、密码找回与重置
            ├── PairPage：创建空间或使用邀请码加入
            └── HomePage：配对成功后的阅读桌面
                  ├── Scene：固定背景与纸笔、台历热区
                  ├── WriteLetter：摘录、出处、批注、照片、草稿与分享
                  │     └── PaperSheet / AnnotationPopover：排版和原文批注
                  ├── CalendarPanel：未读列表与按日期回看
                  ├── ReadLetter：阅读、查看批注与照片、回应
                  └── SettingsPanel：昵称、对方信息、背景音乐、退出
```

`src/preview.jsx` 使用本地演示数据复用上述组件，不连接 Supabase。

## 当前数据结构

| 表或存储 | 当前含义 |
|----------|----------|
| `profiles` | 账号对应的昵称资料 |
| `pairs` | 两人的分享空间与邀请码 |
| `letters` | 一条分享内容：正文、批注、照片路径、展示样式和状态 |
| `reactions` | 对方对一条分享内容的一次普通回应 |
| `annotation_replies` | 阅读者针对原文选区的批注回复，与分享者原批注分开存储 |
| `letter-images` | 内容附带的私有照片文件 |
| IndexedDB `xunchang-drafts` | 当前浏览器中按环境、账号和空间隔离的草稿 |

### 内容字段

| `letters` 字段 | 用途 |
|----------------|------|
| `id` | 草稿生成并在分享重试中复用的 UUID，用于确认是否已经保存 |
| `pair_id` / `sender_id` | 所属分享空间与分享者 |
| `content` | 原文与附在正文末尾的出处 |
| `annotations` | 批注数组，每项含 `id`、`start`、`end`、`quote`、`note` |
| `images` | Storage 对象路径数组 |
| `stationery` | 纸张展示样式；当前新内容统一为 `cream`，保留旧样式的读取兼容 |
| `status` | 历史命名的内容状态，见下表 |
| `sealed_at` | 记录创建时间，也是台历归日依据 |
| `delivered_at` / `read_at` | 分享时间与对方首次已读时间 |

批注的选区起止使用 Unicode 码点偏移。前端将其与 DOM 的 UTF-16 偏移转换，数据库检查原文一致、选区有效且不重叠。批注当前无 100 字上限，最后一条迁移替换了早期的长度检查。

出处是正文的一部分，没有独立的作者、作品或链接字段。不要将「加出处」介绍为自动引用解析。

### 内容状态

| 存储值 | 当前含义 |
|--------|----------|
| `sealed` | 旧版未分享内容，仅本人可见 |
| `delivering` | 历史过渡状态，界面归入本人的未分享内容 |
| `delivered` | 已分享，另一方尚未打开 |
| `read` | 另一方已打开 |

当前分享操作直接写入 `delivered`；状态名沿用旧值，没有等待信鸽或送达动画的环节。

### 回应

`reactions` 使用 `letter_id`、`pair_id`、`user_id`、`emoji`、`note` 和 `created_at`。`letter_id` 唯一，每条内容一次回应；只有另一方可提交。`emoji` 为 `coffee`、`heart`、`thumb`、`dog` 之一，文字回应不设字数上限，支持换行。

## 同步与可靠性

- `useLetters` 分别订阅当前空间 `letters`、`reactions` 和 `annotation_replies` 的 Realtime 变化，正文、普通回应和批注回复可独立重试。
- 页面重新可见或网络恢复后重新读取内容；回应与正文可分别重试。
- `sendLetter` 上传附件前确认私有存储就绪，附件使用带内容哈希的路径。
- 分享使用同一个草稿 UUID 重试，核对正文、批注与附件是否一致，避免重复插入。
- 浏览器草稿按队列保存，使用 Web Locks 防止多个窗口同时编辑。
- 正式页面和预览页面使用不同草稿环境，草稿未同步到其他设备。

## 权限与初始化

内容和照片的可见性由 Supabase RLS 和受限 RPC 检查。未分享内容仅本人可见，已分享内容仅空间双方可见。分享后的正文、批注、照片关联及回应不允许通过当前客户端直接修改或删除。

当前 RPC 包括 `join_pair`、`private_letter_images_ready`、`deliver_sealed_letter`、`mark_letter_read`。后两者保留旧名称，当前分别处理旧内容的确认分享和已读记录。

数据库初始化必须按 [README](../README.md#数据库初始化) 的完整顺序执行。早期脚本的权限及公开图片桶会被后续可靠性脚本加固，不能只执行早期脚本就作为当前部署。

## 批注回复

`annotation_replies` 记录 `id`、`letter_id`、`pair_id`、`user_id`、`start`、`end`、`quote`、`note`、`created_at`。选区使用 Unicode 码点偏移，与原批注相同；回复可以与分享者批注重叠。同一内容、阅读者和选区唯一，UUID 用于确认请求结果并避免重试重复插入。

RLS 只允许已分享内容的空间双方查看，只有另一方可插入，数据库再次验证原文与选区。客户端没有 update / delete 权限，原文及原批注保持独立。

新增迁移为 `supabase/migrations/20261030090000_annotation_replies.sql`。对应功能已通过本地 PGlite 和模拟请求验证；正式部署时先执行新增数据库迁移，再启用新前端。
